Tantangan 1: Invisible Shield & DOM Integrity Mutation

Belum Terpecahkan

Gerbang akses brankas digital "Citadel-Zero" dilindungi oleh sistem proteksi berlapis pada DOM. Tombol otorisasi ditutupi lapisan pelindung anti-klik transparan, tombol terkunci dengan atribut disabled, dan fungsi verifikasi menuntut atribut data integritas data-clearance="1337" serta data-auth-hash="SUPERVISOR_BYPASS". Selain itu, bagian rahasia flag disembunyikan di dalam tag <template> tersembunyi!

💡 Petunjuk Analisis (Tab Elements)
Langkah Eksploitasi:
1. Buka Inspect Element (`Ctrl + Shift + C` atau `F12` $\rightarrow$ Elements).
2. Temukan dan hapus elemen perisai transparan: <div id="citadel-overlay-blocker" ...>.
3. Pada tag tombol <button id="btn-citadel-claim" ...>:
- Hapus atribut disabled="".
- Ubah atribut data-clearance="0" menjadi data-clearance="1337".
- Ubah atribut data-auth-hash="unverified" menjadi data-auth-hash="SUPERVISOR_BYPASS".
4. Klik tombol "Claim Citadel Clearance" yang sekarang dapat diakses. Flag akan digenerate otomatis!
🎯 Target Sandbox: Citadel-Zero Control Gate
🛡️ [SHIELD ACTIVE] Lapisan Pelindung Anti-Click Aktif. Hapus elemen ini via Tab Elements!
Status Clearance Terbaca: Tier-0 (Untrusted)

Tantangan 2: Memory Hooking & Function Monkey-Patching

Belum Terpecahkan

Modul kriptografi bank window.CryptoShield dimuat ke memori browser. Metode CryptoShield.deobfuscateVault() menyimpan ciphertext flag dalam hex, tetapi menolak mendekripsi karena metode validator CryptoShield.isMasterKeyValid() selalu mengembalikan false. Tugasmu: Buka tab Console, lakukan monkey-patching pada fungsi validator atau dekripsi string hex secara manual!

💡 Petunjuk Analisis (Tab Console)
Langkah Eksploitasi:
1. Buka tab Console (`F12` $\rightarrow$ Console).
2. Ketik nama objek untuk menginspeksi: CryptoShield lalu tekan Enter.
3. Amati fungsi isMasterKeyValid. Tulis ulang (monkey-patch) fungsi tersebut di console:
CryptoShield.isMasterKeyValid = function() { return true; };
4. Panggil fungsinya: CryptoShield.deobfuscateVault() atau klik tombol "Jalankan Validasi Memori" di bawah!
5. Flag akan tertera di Console dan layar.
🎯 Target Sandbox: CryptoShield Memory Core
Objek Terdaftar: window.CryptoShield | Status Validator: isMasterKeyValid() === false

Tantangan 3: The Ephemeral Race: Debugger Breakpoint

Belum Terpecahkan

Sistem pertahanan memuat skrip terpisah challenge_sources_vault.js. Ketika tombol clearance diklik, fungsi SourcesVaultEngine.generateClearanceKey() merakit flag rahasia ke dalam variabel lokal ephemeralClearanceFlag, tetapi dalam waktu 50 milidetik variabel tersebut langsung dimusnahkan (`null`). Kamu tidak bisa melihatnya di layar ataupun console biasa—kamu harus menghentikan waktu browser dengan Breakpoint!

💡 Petunjuk Analisis (Tab Sources)
Langkah Eksploitasi:
1. Buka tab Sources (`F12` $\rightarrow$ Sources).
2. Di panel kiri, cari dan buka file challenge_sources_vault.js.
3. Temukan baris di mana let ephemeralClearanceFlag = ... dirakit.
4. Pasang Breakpoint dengan mengklik nomor baris tersebut (akan muncul tanda biru/panah).
5. Kembali ke halaman ini dan klik tombol "Generate Key di Memori".
6. Browser akan seketika membeku (Paused in debugger)!
7. Lihat di panel kanan Scope $\rightarrow$ Local, atau arahkan kursor ke variabel ephemeralClearanceFlag untuk meng-copy flag!
🎯 Target Sandbox: Ephemeral Memory Generator
Target Script: challenge_sources_vault.js
Waktu paruh memori: 50 ms sebelum self-destruct routine diaktifkan.

Tantangan 5: Unsigned JWT 'None' Algorithm & Session Forgery

Belum Terpecahkan

Aplikasi modern ini menyimpan tiket sesi di dalam Session Storage dengan nama auth_bearer_token dalam format JSON Web Token (JWT). Tiket saat ini hanya memiliki role guest. Sistem memiliki kelemahan arsitektur fatal: parser JWT menerima algoritma "none" tanpa tanda tangan! Tugasmu: Bedah token di tab Application, ubah role menjadi admin, set algoritma ke none, dan dapatkan bendera otoritas tertinggi!

💡 Petunjuk Analisis (Tab Application & JWT)
Langkah Eksploitasi:
1. Buka tab Application (`F12` $\rightarrow$ Application $\rightarrow$ Storage $\rightarrow$ Session Storage).
2. Temukan kunci auth_bearer_token. Token berformat: Header.Payload.Signature.
3. Amati bagian payload (bagian kedua di antara dua tanda titik): didecode dari Base64 menghasilkan:
{"user":"guest_user","role":"guest","iat":1698200000}.
4. Ubah role menjadi "admin", ubah header menjadi {"alg":"none","typ":"JWT"}.
5. Encode kembali ke Base64 (bisa gunakan console: btoa('{"alg":"none","typ":"JWT"}') dan btoa('{"user":"guest_user","role":"admin","iat":1698200000}')).
6. Susun token baru tanpa signature: [Base64Header].[Base64Payload]. (akhiri dengan tanda titik).
Contoh: eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0.eyJ1c2VyIjoiZ3Vlc3RfdXNlciIsInJvbGUiOiJhZG1pbiIsImlhdCI6MTY5ODIwMDAwMH0.
7. Simpan nilai baru tersebut di Session Storage, lalu klik tombol "Verifikasi Tiket Sesi JWT"!
🎯 Target Sandbox: Sovereign JWT Authentication Gate
Lokasi Tiket: SessionStorage['auth_bearer_token']
Status Saat Ini: Mendeteksi token...
